# B10 TDC 3600 tape-identity experiment (2026-11-04)

This branch is based on upstream ZuluSCSI commit `18d0e5a1b9f3b4530e5c28e45d06c30ca762f080`, the same clean commit shown as `18d0e5a-dirty` on the user's Blaster during October IPL testing. The local dirty changes are **not** reproduced here.

## Why

The standard built-in `Device = "AS400_CISC"` tape emulates the later TANDBERG/IBM 4100 QIC-1000. The original IBM 9404 B10 came with an IBM 92X4180-branded TANDBERG TDC 3600, firmware I04:, whose SCSI-1 responses differ substantially.

Source: `capture.zip` / `script-v2-captures.txt`, recorded 2026-10-03 with `/dev/sg2`. This capture was made with an empty drive and with a cartridge loaded, not with an AS/400 SCSI bus analyzer.

## Experimental changes (AS400_CISC tape only)

- Standard INQUIRY: exact 51-byte captured SCSI-1 response (peripheral type 1, removable, ANSI level 1).
- MODE SENSE(6), page 0x00, PC=0: exact 24-byte TDC 3600 capture, with medium byte corrected according to current emulated cartridge state.
- MODE SENSE(6), pages 0x10/0x3F: CHECK CONDITION / ILLEGAL REQUEST, matching reported unsupported pages. Precise ASC was **not** captured.
- Medium-type header byte: 0x01 when ejected/empty, 0x00 when cartridge inserted, opposite to the existing 4100 assumptions. An explicit MediumType setting still takes precedence when loaded; do not set MediumType for this experiment.
- READ BLOCK LIMITS: 00 00 80 00 00 01 (max 32768, min 1).
- Suppress later IBM 4100 proprietary INQUIRY pages. The TDC 3600 vendor-specific INQUIRY form **was not captured**, and this rejection behavior is an assumption to test, not a verified copy of the TDC 3600.
- Leave generic tape commands and AWS/SIMH .tap handlers untouched; keep disk code unchanged.

## Suggested target ini configuration

Use the known tape SCSI ID in the actual wiring (verify before testing). For example, if the tape is confirmed as ID 0:

```ini
[SCSI0]
Device = "AS400_CISC"
Type = 5
TapeDensity = 0x0F
```

Use your existing disk sections, disk images, and disk-profile settings unchanged. Use the same tape image configuration as your baseline test. Since this branch changes all AS400_CISC tape targets, **do not use it for later QIC-1000 emulation**.

## A/B test

1. Back up the existing Blaster firmware, SD card configuration, and image files. Record the old firmware hash/dirty marker and SRC sequence.
2. Build this experimental branch for ZuluSCSI Blaster and inspect the GitHub Actions status; do not flash an unverified or failed build.
3. Install only the **Blaster** firmware artifact, with the same disk images and cabling, and an inserted emulated tape image. Verify the startup log shows this branch/commit.
4. Try one IPL; record control-panel SRCs (including function-11 through function-19 words where applicable) and the ZuluSCSI SCSI command/status trace.
5. Compare against baseline: standard INQUIRY, MODE SENSE page 0x00 vs 0x10/0x3F, READ BLOCK LIMITS, any vendor-form INQUIRY requests, and whether the SRC progresses.
6. Restore baseline firmware if the test is worse. The physical machine has not been tested by this branch; no successful IPL is claimed.

## Unverified compatibility aspects

- The captured script says VPDSupported=no for **standard EVPD**. It does not establish how the older drive responds to IBM's proprietary 4100-style INQUIRY form (CDB byte 2 bit 7, page in byte 3).
- Precise REQUEST SENSE data and behavior for the rejected 0x10/0x3F MODE SENSE pages were not captured. Only their failure was reported.
- The captured block descriptor advertises density 0x0F and 512-byte blocks; this does **not** prove that the AS/400 can alternate-IPL from a blank .tap image. A valid tape image is required for a meaningful tape IPL test.
